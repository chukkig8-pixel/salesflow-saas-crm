A Cloud-Based Customer Relationship Management & DevOps Practice System

Architecture Client-Server Multi-tier (React + REST API)
Database MySQL 8.0+ / PostgreSQL (8 Normalized Tables)

1. Executive Summary & Project Overview

SalesFlow CRM is a full-stack, enterprise-grade cloud Customer Relationship Management web application engineered to help modern organizations track leads, manage customer contacts, advance opportunities through standardized sales pipeline stages, schedule rep follow-ups, and automate customer communications.

In addition to its full-stack functional capabilities, the system acts as a demonstration vehicle for Software Quality Assurance (QA) and DevOps engineering practices, incorporating automated REST API test suites, Role-Based Access Control (RBAC) security validation, containerization with Docker, and continuous integration/continuous deployment (CI/CD) pipelines.

3. Database Schema Design (8 Normalized Entities)

The data layer is fully normalized (3NF) to ensure zero data redundancy and ACID compliance:

Table Name Primary Key Key Fields & Constraints Purpose
users id (INT) email (UNIQUE), role (ENUM: admin, sales_manager, sales_executive) System user accounts with RBAC privilege enforcement.
pipeline_stages id (INT) stage_order (UNIQUE), probability (INT), color_hex 6 standardized pipeline lifecycle stages.
contacts id (INT) company, email, FK: assigned_to_user_id Customer decision-makers and organizational accounts.
leads id (INT) lead_source, lead_status, lead_score (0-100), value Prospective accounts with automated scoring.
deals id (INT) amount, close_date, FK: stage_id, FK: contact_id Active sales opportunities managed on the Kanban board.
tasks id (INT) task_type, priority, due_date, status (Pending/Completed) Rep action items, phone calls, demos, and meetings.
notes id (INT) content, related_to_type, related_to_id, FK: author_id Customer meeting minutes and interaction timeline history.
email_logs id (INT) recipient_email, subject, body, status Delivery logs of emails sent via integrated templates.

4. The 6 Standardized Pipeline Stages

Sales opportunities transition through 6 sequential phases with pre-calculated win probabilities:

  1. Stage 1: Lead In / Discovery (10% Probability) – Initial prospect inquiry identified; discovery questionnaire conducted.
  2. Stage 2: Contact Made / Qualification (30% Probability) – Budget, Authority, Need, and Timeline (BANT criteria) validated.
  3. Stage 3: Proposal Sent / Pitch (50% Probability) – Formal technical proposal and customized pricing structure presented.
  4. Stage 4: Negotiation / Review (75% Probability) – Commercial SLA, discount terms, and contractual sign-off in progress.
  5. Stage 5: Closed Won (100% Probability) – Deal executed, payment received, client onboarded.
  6. Stage 6: Closed Lost (0% Probability) – Deal declined or lost to competitor with recorded loss justification.

5. Software Testing & Quality Assurance (QA) Suite

An automated regression test suite (implemented in test_salesflow_crm.py) validates 10 automated test suites with a 100% pass rate:

  • Schema & Constraint Validation: Verifies that exactly 6 pipeline stages are maintained and lead scores reside between 0 and 100.
  • RBAC Security Tests: Validates permission isolation between Administrator, Sales Manager, and Sales Executive personas.
  • Database Foreign Key Integrity: Confirms relational consistency between deals, contacts, and assigned account reps.
  • OWASP Top 10 Security: Enforces parameterized SQL queries to prevent SQL Injection and input escaping to block Cross-Site Scripting (XSS).
  • Load & Latency Benchmarks: Confirms sub-50ms API response latency under simulated concurrent k6/JMeter workload.

6. DevOps, Docker Containerization & AWS Cloud Infrastructure

  • Docker Multi-Stage Build: Encapsulates runtime dependencies inside a minimal, production-hardened Linux container with automated healthcheck probes.
  • Continuous Integration (CI/CD): GitHub Actions workflow (.github/workflows/ci-cd.yml) executes automated testing, code quality linting, container compilation, and cloud deployment on every commit.
  • Cloud Architecture:
    • Compute: AWS EC2 instances orchestrating containerized services.
    • Database: AWS RDS running managed MySQL 8.0 with Multi-AZ automated backups.
    • Storage & CDN: AWS S3 bucket for assets coupled with Amazon CloudFront edge caching.
